# ForgeSight 后端实现清单

> 位置：`forge-sight/backend/`（Python，依赖安装在 venv 虚拟环境）
> 前置确认：MySQL 8 已就绪、官方数据已导入 `forge_sight`、LLM API Key 已有
> 参考：`datafoundry-main` 的分层思路（data-gateway 只读守卫 / metadata / knowledge / agent-runtime），仅借鉴思路不照搬代码
> 关联文档：`../A07_企业数据底座智能问析Agent_需求深度分析.md`、`../ForgeSight_系统运行流程说明.md`

## 0. 关键决策（已锁定）

| 决策 | 结论 |
|---|---|
| 数据库方言 | **MySQL 8**（以 `database/schema.sql` 为准；前端 mock 文案中的「PostgreSQL」后续统一修正） |
| 平台数据存储 | 业务库 `forge_sight` 保持只读；平台自身数据（知识、会话、审计、元数据登记）迁移至 PostgreSQL `forge_sight_app` |
| 指标知识分层 | 企业统一业务语义独立于物理数据库；每个数据源分别维护 SQL 方言、表、字段、过滤条件和验证状态 |
| 业务库访问 | 专用只读账号，禁止写权限 |
| LLM 接入 | OpenAI 兼容协议，Key 只存服务端 `.env`，不进入前端与对话上下文 |
| 语义层原则 | 知识定义全局共享，表字段绑定按数据源各自维护 |

技术栈：`FastAPI + Uvicorn + SQLAlchemy + PyMySQL + sqlglot + openai SDK + scikit-learn + pydantic-settings + pytest`

## 1. 目标目录结构

```
backend/
  .venv/                  # 虚拟环境（不入库）
  .env                    # DB 连接、LLM Key（不入库）
  .env.example
  requirements.txt
  app/
    main.py               # FastAPI 入口、路由装配、CORS
    config.py             # pydantic-settings 配置
    db/
      business.py         # forge_sight 只读连接
      platform.py         # forge_sight_app 读写连接
      models.py           # 平台库 ORM 模型
    gateway/              # data-gateway：只读执行器 + SQL 校验（安全红线）
      sql_validator.py    # sqlglot AST：仅 SELECT、白名单、禁多语句、行列限制
      executor.py         # 受控执行：行数、超时、结果检查
    audit/                # 审计日志服务
    metadata/             # 元数据扫描与资源登记
    knowledge/            # 主题/对象/指标/规则
    retrieval/            # 语义检索（召回指标+表+关系）
    agent/                # 问析流水线（七步）、会话、澄清、拦截
    llm/                  # LLM provider 封装
    modeling/             # sklearn 建模引擎
    reports/              # 报告生成
    api/                  # 路由层，按前端 src/api/ 契约分组
  tests/
```

### 阶段 4 · 语义检索（依赖 2 + 3）

- [x] 4.1 检索服务：按自然语言问题召回相关指标口径、候选表字段、已登记关联路径（关键词/规则匹配）
- [ ] 4.2 （可选增强）embedding 向量检索；保留为数据规模扩大后的召回增强，不作为当前主链路依赖

**输出形态**：给 Agent 的「语义上下文包」——只含本次问题相关的真实表字段与口径，禁止全库自由发挥（可信机制 T01）。✅ 已达成

> 实现摘要：新增 `POST /api/retrieval/context`。检索器会规范化中文问题，识别分析主题和趋势/排行/相关性/异常/报告意图，只召回“企业口径已发布 + 当前数据源物理绑定已验证”的指标；再从指标绑定与业务对象语义中选择最小表集合，并只补入平台库已登记的真实关联路径。上下文包显式携带指标版本、物理公式、字段映射、候选表字段、业务规则、只读策略、`allowedTables`、`allowedColumns` 与 `joinPaths`，供阶段 5 的 SQL 生成和校验直接消费。检索按 `sourceId` 全链路隔离，未知数据源返回 404，无匹配时返回空白名单而不是猜测。当前采用可解释的词法/规则检索，向量召回通过 `retrieval.strategy` 留有后续扩展位置。

## 4. 反幻觉与质量红线（后端同样适用）

1. 表结构、字段、枚举、指标口径以 `data/数据介绍.md` 与 `database/schema.sql` 为唯一权威，禁止编造
2. 业务库只允许只读访问；平台数据一律写 `forge_sight_app`
3. LLM 生成的 SQL 必须过 sqlglot 校验 + 白名单后才允许执行，无例外路径
4. 结论中的数值必须来自执行结果，生成后做数值核对
5. 每个阶段完成后跑 `pytest` 并用前端页面对应功能验证
