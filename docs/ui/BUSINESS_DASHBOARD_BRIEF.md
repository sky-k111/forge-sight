# 业务看板界面改造

## 已确认边界

- Operate：面向制造业业务人员，日常看概览，再进入问析调查。
- 企业、账号、数据源隔离；个人可编辑布局。
- 只改此页与导航名称，保留 ForgeSight 和其他页面。
- 推荐名称为“业务看板”，原路由保持兼容。

## 视觉方向

用户已指定成熟企业软件参照，而非开放式品牌实验：浅色工作区、墨色文字、克制的单一蓝绿色强调、细边框、小圆角、对齐的数据栅格、紧凑工具栏。中文正文保持可读，不照搬英文软件的小字号。重点由数据字号、图表面积和内容密度建立，不由多种彩色卡片建立。

## 三种布局对照

1. **数据概览型**：四个紧凑指标，上方统一筛选，中部趋势与维度对比，下方近期调查。
2. **分析工作区型（已选定）**：连续指标带和大趋势图，右侧独立调查栏；更集中地查看一个核心指标。用户确认“B 很不错”，实施以此为准。
3. **任务驱动型**：待继续调查与快捷问析占据上方，紧凑指标和趋势置于下方；更偏个人工作台。

三张均沿用同一视觉语言，只比较布局、密度与阅读顺序。图中的数值和曲线必须标为“布局示意 · 非真实数据”。效果图不表示功能已上线，也不决定最终查询范围。

## 借鉴的交互细节

- 设置面板采用明确标签、字段旁帮助与紧凑分段控件。
- 布局拖动只在编辑模式开启；浏览模式不易误触。
- 编辑时固定保存／取消栏，并显示未保存状态。
- 添加组件时明确指标、业务维度、时间范围与图表类型。
- 保留键盘排序与移动端纵向排列的实现位置。

## 数据实现要求

- 不直接展示旧前端固定的“昨日产量”“良率”“完成率”。
- 数据源、口径、时间范围、权限和组件错误分别表达。
- 保存布局及受治理查询定义，不保存截图，不允许任意 SQL 组件。
- 刷新固定看板不应重新调用 LLM 来规划每个组件。
- 没有绑定、没有记录、查询失败不能变成零值或虚构成功。
- 拖拽／缩放使用 [React-Grid-Layout](https://github.com/react-grid-layout/react-grid-layout) 2.2.4，React peer 范围兼容项目 React 19。

## 当前状态

B 方案已完成前后端实施：

- 看板配置按企业＋账号＋数据源隔离，使用乐观版本防止多窗口覆盖。
- 默认组件由当前数据源已发布、已验证且可执行的指标动态生成，不写死指标 ID。
- 查询只接受指标、维度、展示类型和时间预设，继续走统一只读网关，不为每个组件调用 LLM。
- 支持阅读/编辑分离、拖动、缩放、键盘移动、添加、删除、取消、恢复默认与保存；删除后的工作区组件可从添加弹窗恢复。
- 支持组件级低饱和强调色和紧凑／标准／重点快捷尺寸，颜色不覆盖业务状态语义，所有调整与布局统一保存。
- 图表选择按查询数据形态约束：汇总值使用大数字；时间趋势支持折线、面积、柱状；分类对比支持横向条形、柱状、饼图、环形图、矩形树图和数据表。散点、热力、桑基和地图需双指标、双维度或地理字段，当前查询契约不满足时不提供伪选项。
- 饼图、环形图和矩形树图只接受非负且至少一个正值的分类结果；不满足时回退为数据表并解释原因，避免错误占比。
- “可用指标”不再截断前 7 项，卡片内滚动展示全部指标，并固定显示总数和浏览提示。
- 实机验收包括桌面阅读态、编辑态、添加弹窗与 390px 窄屏；浏览器控制台无错误。
