# R00 智能生成与自动发布执行计划

> 状态：已完成
>
> 大任务：`R智能生成与自动发布`
> 目标：复用现有分析 Run、Task 和 Artifact，按订阅周期自动生成结构化周报，通过校验门后直接发布。
> 前置依赖：M 业务数据模型与迁移；Q 提供有效用户身份
> 协作依赖：V 提供校验和文件契约，N/E 消费发布事件

## 一、交付边界

本任务负责调度、数据预检、报告章节编排、结果汇总、状态流转和自动发布事件。PDF/Excel 渲染属于 V，消息属于 N，邮件属于 E。

本任务不得恢复人工提交复核、批准或发布的必经流程。

```json
{
  "eventType": "report.version.published",
  "eventId": "evt_xxx",
  "reportId": "report_xxx",
  "versionId": "rv_xxx",
  "subscriptionId": "sub_xxx",
  "period": {"start": "...", "end": "...", "timezone": "Asia/Shanghai"},
  "audienceScopeHash": "sha256...",
  "publishedAt": "..."

```

事件消费者必须按 `eventId` 或业务幂等键去重。

## 五、风险与回滚

- 风险：自动发布放大错误结论。缓解：硬校验门、证据绑定、数据异常版和逐模板灰度。
- 风险：调度器重复执行。缓解：数据库唯一约束、租约和幂等消费。
- 风险：大范围用户产生高负载。缓解：按报告生成一次，按权限分群或生成专属版本，触达异步化。
- 回滚：可禁用具体订阅或全局调度开关；已发布版本不删除，必要时发布替代版本。

## 六、完成定义

- R01～R09 全部完成。
- 周报可定时、可恢复、可追溯地生成。
- Agent 校验通过后直接发布，无人工复核阻塞。
- 数据不足时不伪造结论。
- 重复调度和重试不产生重复报告版本。
- 发布事件可被文件、消息和邮件链路幂等消费。
- 发布事件与版本状态原子提交，进程崩溃不会永久丢失下游任务。

## 七、实现记录（已合并）

- 以订阅时区计算已结束的自然周，并为新订阅初始化下一次运行时间。
- 到期扫描在同一事务中创建报告、版本、章节、分析会话和持久化 Agent Run；数据库唯一键负责调度幂等。
- 版本冻结数据覆盖、对比周期、章节计划、工作流和模型策略快照；缺指标时明确标记为数据异常。
- 章节结论继续复用阶段五 Task 与 Artifact，报告保存任务、证据和校验结果的追溯关系。
- 自动发布使用确定性硬校验；缺章节结论或 Artifact 时进入 `validation_failed`，不产生发布事件。
- 校验通过后直接发布，不经过人工审核，并在同一事务写入 `report.version.published` Outbox 事件。
- 订阅失败互相隔离且保留原运行时间待重试；Agent Run 沿用既有租约恢复和查询自动重试能力。
