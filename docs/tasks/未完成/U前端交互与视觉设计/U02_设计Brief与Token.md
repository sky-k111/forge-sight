# U02 设计 Brief 与 Token

> 状态：待产品确认
>
> 设计方向：经营简报 + 渐进式可追溯证据
>
> 平台：响应式 Web；桌面 1440px 与移动端 375px 为主要验收尺寸
>
> 依赖：[U01 用户与竞品研究结论](./U01_用户与竞品研究结论.md)

## 一、设计目标

ForgeSight 周报首先是一份经营简报，其次才是分析工具。视觉设计必须让用户按以下顺序
理解内容：

1. 最近一个周期发生了什么；
2. 哪项变化最重要；
3. 哪个异常需要立即处理；
4. 建议谁在什么时候完成什么行动；
5. 需要核查时，数据和指标依据在哪里。

桌面端目标是在一分钟内完成前四项，移动端目标是在三十秒内完成前三项。图表必须承担
比较和解释任务，不能只是装饰或原始数据的重复绘制。

## 二、视觉方向

### 决策：浅色工业编辑风

使用略带青灰的纸张色背景、矿物蓝强调色、清晰列网和编辑式长页排版。报告阅读页借鉴
经营简报和年度报告，管理页面保持工业控制台的密度与状态明确性。

选择原因：制造数据需要稳定、可信和长时间可读；浅色背景适合图表、表格、打印和会议
投屏，编辑式节奏可以避免“相同卡片平铺”的模板感。

未采用方案：

- 深色科技大屏：适合监控墙，但不适合长文阅读、打印和移动端临时查看；
- 高饱和蓝紫渐变：容易产生通用 AI 产品观感，也会与异常语义色争夺注意力。

## 三、信息优先级

### 周报桌面首屏

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 报告标题 / 周期 / 组织范围 / 数据更新时间            PDF  Excel   │
├───────────────────────────────────────────────┬─────────────────────┤
│ 一句话总体结论                                │ 最严重异常          │
│ 本周是否正常、主要变化、是否需要介入          │ 影响、状态、行动    │
├───────────────────────────────────────────────┴─────────────────────┤
│ 产量      达成率      良品率      停机时长      库存      异常数    │
├───────────────────────────────────────────────┬─────────────────────┤
│ 主趋势图：本期 / 上期 / 目标 / 异常标注       │ 结构贡献 / Pareto   │
└───────────────────────────────────────────────┴─────────────────────┘
```

眼睛接触顺序：

1. 一句话结论；
2. 关键指标变化；
3. 最严重异常与行动；
4. 主趋势和贡献来源；
5. 后续异常表、进展、行动表、数据质量与证据。

### 周报移动端首屏

```text
报告标题 / 周期
一句话总体结论
最严重异常
横向滚动关键指标
主趋势简化图
PDF / Excel 操作
```

移动端不显示桌面章节侧栏和固定证据栏；证据通过行内“查看依据”抽屉展开。

### 决策：结论先于图表，图表先于证据

选择原因：管理者先判断，业务人员再分析，争议发生时才核查证据，符合三类用户的共同
阅读顺序。

未采用方案：

- 图表墙优先：用户仍需自行寻找结论，无法保证一分钟阅读目标；
- 证据三栏常驻：可信但压迫主阅读区，移动端也无法成立。

## 四、字体系统

### 颜色决策

- 产品 UI 与数据正文：`Segoe UI Variable` + `Microsoft YaHei UI` 中文系统栈；
- 周报大标题与一句话结论：`Source Han Serif SC` / `Noto Serif CJK SC` 宋体栈；
- 数字不新增第三字体，使用 UI 字体的 `tabular-nums` 特性。

选择原因：无衬线字体适合高密度筛选、表格和状态；宋体只在报告标题和主结论使用，增加
正式简报气质，又不会影响数据扫描。两套字体在中文正文中的字面高度接近。

未采用方案：

- 全部使用无衬线：稳定但报告与普通管理页面缺少视觉区分；
- 全部使用宋体：长表格、筛选和小字号状态的辨识效率较低。

### 字号比例

基础正文为 16px，采用约 1.25 的比例构成字号级别。单个页面最多同时使用其中三级。

| Token | 字号 / 行高 | 用途 |
| --- | --- | --- |
| `--text-label` | 13px / 18px | 元数据、表头、辅助标签；任何文字不得小于 12px |
| `--text-body` | 16px / 24px | 正文、表格、控件 |
| `--text-title` | 20px / 24px | 区块标题、消息标题 |
| `--text-display` | 25px / 28px | 页面标题、周报主结论 |
| `--text-hero` | 31px / 35px | 仅周报桌面标题；移动端回退到 display |

正文舒适行长为 45～72 个中文全角字符；管理摘要最大宽度 760px。英文大写只用于不超过
三个词的辅助标签，字距 0.08em；正式中文标题不使用全大写英文装饰。

## 五、颜色系统

### 间距决策

矿物蓝 `#285D72` 是唯一主强调色，仅用于主操作、当前筛选和主要数据系列。状态使用常规
语义色并同时搭配文字或图标。

选择原因：矿物蓝与制造业设备、图纸和数据可信感一致，饱和度低于常见 SaaS 亮蓝，能
让异常红和预警琥珀色保持真正的注意力价值。

未采用方案：

- 继续使用多个蓝、紫、青作为同级品牌色：图表系列和交互状态容易混淆；
- 大面积深色底：图表打印和长时间阅读成本较高。

### 基础 Token

| Token | 值 | 用途 |
| --- | --- | --- |
| `--color-canvas` | `#F3F5F4` | 应用背景 |
| `--color-paper` | `#FBFCFB` | 周报纸面、主要表面 |
| `--color-surface` | `#FFFFFF` | 控件和浮层 |
| `--color-surface-muted` | `#EFF2F1` | 分组背景 |
| `--color-line` | `#DCE3E1` | 内容分隔线 |
| `--color-line-strong` | `#71837D` | 控件边界、图表轴线 |
| `--color-ink` | `#182329` | 主文字 |
| `--color-ink-2` | `#394A50` | 次级正文 |
| `--color-muted` | `#5D6D72` | 元数据；在 paper 上对比度 5.24:1 |
| `--color-primary` | `#285D72` | 主操作、主图系列；在 paper 上 7.04:1 |
| `--color-success` | `#176B57` | 正常、改善；在 paper 上 6.23:1 |
| `--color-warning` | `#8A5A12` | 关注、延迟；在 paper 上 5.75:1 |
| `--color-critical` | `#A33A36` | 严重、失败；在 paper 上 6.35:1 |
| `--color-primary-soft` | `#E9F1F3` | 当前项低强调背景 |
| `--color-success-soft` | `#E9F3EF` | 正常状态背景 |
| `--color-warning-soft` | `#F7F0E5` | 关注状态背景 |
| `--color-critical-soft` | `#F8ECEB` | 严重状态背景 |

主文字在 paper 上对比度 15.57:1，次级正文为 9.00:1。重要控件边界使用 strong line，
达到非文本 3:1 要求；普通内容分隔线不独立承担交互边界。

项目现有深色模式继续保留。深色模式使用去饱和深灰表面，不采用纯黑背景；报告的信息
顺序、字体层级和语义色不变，图表色切换为对应的高明度版本。PDF 始终使用浅色纸面，
保证打印一致性。

### 状态表达

- 正常：对勾图标 + “正常/改善”文字 + success；
- 关注：三角图标 + “关注/延迟”文字 + warning；
- 严重：感叹图标 + “严重/失败”文字 + critical；
- 处理中：进度图标 + “生成中/等待附件/重试中”文字 + primary；
- 未知：问号图标 + “结果待核对”文字 + ink-2。

任何状态都不能只依赖颜色。

## 六、间距、形状与密度

### 决策

采用 8px 主网格与 4px 精细网格：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64`。页面区块
间隔 32px，组内间隔 8～16px，明确满足“组内小于组间”。

选择原因：现有 ForgeSight 已接近 4px 基础节奏，统一后可以在不牺牲信息密度的情况下
形成清楚层级。

未采用方案：

- 全部使用大留白：企业管理页面信息效率过低；
- 每个组件自由定义间距：页面之间会失去统一节奏。

### 形状

| Token | 值 | 用途 |
| --- | --- | --- |
| `--radius-status` | 4px | 状态标签、小型提示 |
| `--radius-control` | 8px | 按钮、输入、筛选 |
| `--radius-section` | 12px | 图表、内容分组 |
| `--radius-overlay` | 16px | 对话框、抽屉 |

报告纸面本身不使用悬浮卡片圆角；只对内部图表框和需要区分的操作组件使用圆角。阴影
仅用于浮层与固定工具条，普通报告区块通过留白和分隔线组织。

### 密度

- 桌面表格行高 48px，移动端主要操作高 48px；
- 所有触控目标至少 44×44px；
- 筛选栏高度 40px，表头高度 40px；
- 表格文字 14～16px，数字右对齐并启用等宽数字；
- 长文字允许两行或完整换行，不能用截断隐藏关键异常和行动。

## 七、图表设计规范

### 核心原则

每张图必须在标题中回答一个业务问题，采用“结论标题、范围副标题、图形、文字摘要、
来源”的结构。例如：

> 焊接工序贡献了本周 62% 的新增缺陷
>
> 2026-08-03 至 2026-08-09，对比上一完整自然周

### 决策：直接标注、有限系列、结论型标题

选择原因：直接标注减少视线在图例和数据之间往返；有限颜色确保重要系列和异常点突出；
结论标题让管理者不操作图表也能获取信息。

未采用方案：

- 多色分类图例：类别稍多就失去优先级，也不利于色觉差异用户；
- 仅用“良率趋势”等名词标题：需要用户自行解读，无法保证快速阅读。

### 通用图表 Token

```css
:root {
  --chart-primary: #285D72;
  --chart-comparison: #9BAAA6;
  --chart-success: #176B57;
  --chart-warning: #8A5A12;
  --chart-critical: #A33A36;
  --chart-grid: #DCE3E1;
  --chart-axis: #5D6D72;
  --chart-tooltip-bg: #182329;
  --chart-tooltip-text: #FBFCFB;
  --chart-line-width: 2.5px;
  --chart-marker-size: 5px;
  --chart-desktop-height: 320px;
  --chart-mobile-height: 240px;
}
```

### 图表映射

| 业务问题 | 图表 | 视觉要求 |
| --- | --- | --- |
| 本周走势是否偏离目标 | 折线图 | 本期实线、上期浅灰、目标虚线、异常点带文字标注 |
| 哪个工序贡献最大 | 排序横条图 | 降序、末端直接标值、关键条使用 primary，其余中性灰 |
| 哪类缺陷决定整体问题 | Pareto | 降序条形 + 累计线，标注 80% 阈值，不使用双重彩色图例 |
| 异常集中在哪天和哪条线 | 热力图 | 4～5 级单色深浅，严重格带图标或数值，不只靠颜色 |
| 两项指标是否相关 | 散点图 | 显示趋势线、样本数和相关程度文字，不暗示未经验证的因果 |
| 少量精确值比较 | 表格 | 不为两三个值强行绘图 |

### 图表细节

- 坐标轴从业务合理起点开始；截断轴必须明确标识；
- 网格线只保留主要水平线，线宽 1px，不使用外框；
- 单位放在轴标题或指标名称中，不重复写在每个标签；
- 最多同时显示一个主系列、一个对比系列和一个目标系列；
- 重要异常直接标注，普通点通过键盘聚焦或数据表查看；
- Tooltip 仅提供补充信息，关键结论不得只存在于悬停态；
- 每张图提供 1～2 句 `aria-describedby` 文字摘要和可访问数据表；
- 图表首次进入可使用 320ms 淡入/绘制，筛选后只做 200ms 状态过渡，不重复表演。

## 八、图片规范

### 决策：主题配图位于指标之后，不占据首要信息位

每类周报可以使用一张授权或项目自有的业务主题图，例如生产线、质量检测、设备维护或
库存作业。图片必须：

- 与报告主题相符，并标注“主题配图，非数据证据”；
- 有说明、来源和具体替代文本；
- 使用 16:9 或 3:2 裁切，桌面高度不超过 240px；
- 与数据洞察主图并排或位于其后，不覆盖文字和图表；
- 加载失败时使用包含业务结论的静态数据概览，不显示破图。

选择原因：图片提供主题和编辑式节奏，但不应误导用户把场景照片当作经营证据。

未采用方案：

- 首屏全宽照片：会挤压最近重要信息并降低企业工具的信息效率；
- 无关抽象插画：不能帮助理解制造业务，属于纯装饰。

## 九、页面层级

### 1. 邮箱绑定与验证门禁

视觉顺序：品牌与价值说明 → 当前账号 → 邮箱输入/已绑定邮箱 → 验证码 → 安全说明。

- 激活时刻：邮箱验证成功并进入消息中心或原目标页面；
- 登录保持最少字段；注册增加邮箱字段；
- 未验证用户进入独立页面，不渲染工作台侧栏；
- 验证码为一个可粘贴的 6 位输入框，避免六格焦点跳转；
- 重发倒计时显示具体剩余秒数，失败保留邮箱和已输入内容。

### 2. 消息中心

视觉顺序：未读数与分类 → 筛选 → 消息列表 → 行内详情或详情抽屉。

- 导航入口固定显示未读数；
- 分类为全部、Agent 周报、管理员公告；
- 每行显示来源、标题、两行摘要、时间、严重度、已读状态和主操作；
- 打开消息后乐观标记已读，API 失败时恢复并给出文字提示；
- 列表用于浏览，不使用同尺寸消息卡网格。

### 3. 周报列表

视觉顺序：最新一期摘要 → 状态筛选 → 可比较列表。

- 默认按发布时间倒序；
- 展示周期、版本、总体结论、严重异常数、数据完整度、发布时间；
- 分开显示报告状态、文件状态和邮件投递状态；
- 默认流程不出现“待复核/通过复核/人工发布”；
- 主操作为“查看周报”，PDF 与 Excel 为明确的次操作。

### 4. 周报详情

视觉顺序使用第三节首屏结构，后续依次为：

1. 业务主题图或数据洞察主图；
2. 趋势与结构分析；
3. 异常明细表；
4. 本周重点进展；
5. Agent 行动建议表；
6. 数据质量；
7. 默认收起的指标、数据范围、Artifact 和 SQL 证据；
8. 版本与文件附录。

### 5. 管理员公告

视觉顺序：公告列表与状态 → 创建/编辑表单 → 接收范围预览 → 发布结果。

- 表单字段为标题、正文、优先级、接收范围、置顶、有效期；
- 发布前必须显示接收人数和组织摘要；
- 发布与撤回是明确的文字按钮，撤回要求填写原因；
- 业务用户路由守卫和导航同时隐藏管理入口。

### 6. 邮件投递管理

视觉顺序：失败与未知数量 → 筛选 → 高密度表格 → 重发结果。

- 展示掩码邮箱、对象类型、状态、尝试次数、错误类别和下次重试；
- `unknown` 明确显示“先核对服务商记录”，租约到期后才允许显式确认重发；
- 人工重发复用同一投递记录，成功后行内状态更新；
- 详情不显示 SMTP 原始错误或完整地址。

## 十、完整状态设计

| 页面 | 加载 | 空 | 错误 | 权限 | 成功 |
| --- | --- | --- | --- | --- | --- |
| 邮箱门禁 | 按钮内进度，保留表单 | 不适用 | 明确邮箱/验证码问题与恢复动作 | 未登录回登录页 | 显示已验证并进入目标页 |
| 消息中心 | 6 行骨架 | 当前分类无消息，可“查看全部” | 保留筛选并可重载 | 401 登录，404 隐藏对象 | 未读数即时减少 |
| 周报列表 | 摘要带 + 5 行列表骨架 | 说明无报告或筛选无结果 | 保留筛选，提供重试 | 仅显示数据范围内报告 | 新报告按真实状态出现 |
| 周报详情 | 身份、指标和图表骨架 | 缺少章节时说明生成中 | 保留内容并局部重试 | 显示“报告不存在或无权访问” | 文件就绪可下载 |
| 公告管理 | 表格骨架 | 说明还没有公告并提供“创建公告” | 保留草稿输入 | 业务用户不显示路由 | 发布后显示接收人数 |
| 投递管理 | 表头 + 8 行骨架 | 说明当前筛选无投递 | 错误不含敏感服务商正文 | 非管理员 403 页面 | 重发后更新原行和尝试次数 |

### 决策：内容形状骨架 + 局部恢复

选择原因：1～10 秒的接口加载使用与真实页面相似的骨架，错误发生时保留可用内容和用户
输入，避免整页闪烁或丢失上下文。

未采用方案：

- 所有页面中央旋转图标：不能预告内容结构，长等待缺少进度含义；
- 任何请求失败都清空整页：会丢失筛选、草稿和已经加载的信息。

## 十一、引导与文案

### 引导决策

不增加教程轮播。邮箱验证页直接说明价值：“验证邮箱后，周报和公告可以发送到你的
邮箱”。消息空状态和报告空状态提供情境内下一步。

激活时刻是：用户验证邮箱后，成功打开第一条周报消息并在详情首屏看到总体结论。

未采用方案：

- 首次登录多页产品介绍：延迟核心任务，用户无法立即验证价值；
- 强制完成多个资料字段：与邮箱绑定和周报阅读无关。

### 语气表

| 场景 | 语气 | 示例 |
| --- | --- | --- |
| 正常信息 | 简洁、客观 | “数据更新至 8 月 10 日 08:30” |
| Agent 结论 | 明确但不过度确定 | “本周良率下降 1.8 个百分点，主要集中在焊接工序。” |
| 建议 | 可执行、注明来源 | “Agent 建议：8 月 15 日前复核焊接参数。” |
| 错误 | 严肃、可恢复、不责怪 | “验证码已过期，请重新发送后再验证。” |
| 危险操作 | 说明影响 | “撤回后，用户不能再从消息中心打开该公告。” |

按钮统一使用动宾结构：“发送验证码”“验证并进入工作台”“查看周报”“下载 PDF”
“发布公告”“确认重发”。不使用“提交”“确定”“好的”等缺少对象的文案。

## 十二、动效

### 动效决策

只保留四类功能性动效：

- 筛选与行状态：200ms `cubic-bezier(0.2, 0, 0, 1)`；
- 证据抽屉与移动筛选面板：280ms `cubic-bezier(0.22, 1, 0.36, 1)`；
- 成功提示进入：240ms，同一操作不重复播放；
- 图表首次绘制：320ms，后续筛选只做 200ms 淡变。

`prefers-reduced-motion: reduce` 下取消位移、缩放和绘制动画，只保留即时状态变化。

选择原因：动效用于解释状态归属和空间关系，不用于营造科技感。

未采用方案：

- 数字滚动和逐卡片入场：频繁阅读时产生干扰并延迟信息出现；
- 弹跳或线性移动：不符合企业工具的稳定感，也不利于运动敏感用户。

## 十四、A4 PDF 对应关系

Web 和 PDF 共享信息顺序、颜色语义、字号关系和图表规范，不要求像素完全一致。

| Web | A4 PDF |
| --- | --- |
| 1360px 最大阅读宽度 | A4 210×297mm，左右页边距 14mm |
| 31px 报告标题 | 18pt 报告标题 |
| 25px 一句话结论 | 13pt 宋体主结论 |
| 16px 正文 | 9.5～10pt 正文，行距 1.45 |
| 6 项横向指标带 | 3×2 指标表，保持单位和环比 |
| 8/4 栏主趋势与贡献图 | 170×72mm 主趋势，次图下一行或 82×65mm 双栏 |
| 屏幕表格 48px 行高 | 7～8mm 行高，跨页重复表头 |
| 行内证据抽屉 | 文末“口径与证据”附录 |
| 主题配图最大 240px | 最大 170×65mm，保留说明、来源和替代文字对应描述 |

分页规则：标题、图表标题和图形不拆页；行动建议表优先整体开始于新页；每页页脚显示报告
ID、版本、周期和页码。颜色打印失效时，状态仍通过图标、文字和线型区分。

## 十五、验收标准

- 1440px 首屏同时看到总体结论、关键指标、最严重异常和主趋势；
- 375px 首屏不出现横向页面滚动，关键操作至少 44px；
- 图表均有结论型标题、周期、单位、来源、文字摘要和可访问数据；
- 所有正文至少 16px，辅助文字不小于 12px；
- 没有人工复核作为自动周报主流程；
- 图片不遮挡或替代业务结论，并明确“非数据证据”；
- 证据默认收起，展开不超过两层；
- 加载、空、错误、权限和成功状态均按状态矩阵实现；
- 最终真实浏览器输出通过 senior-designer Web 43 项检查。
