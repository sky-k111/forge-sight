# N00 消息中心与公告执行计划

> 状态：实施完成，待合并
>
> 大任务：`N消息中心与公告`
> 目标：为 Agent 周报和管理员公告提供统一、可筛选、按用户记录已读状态的站内消息入口。
> 前置依赖：M 消息/公告模型，Q 用户身份
> 后续依赖：E、U、T

## 一、交付边界

本任务负责消息与公告后端领域服务和 API，不负责邮件传输、周报正文生成或 Web 页面实现。消息中心不是聊天系统，不实现回复和确认回执。

- 审计：`backend/app/audit/service.py`。

## 四、API 建议

```text
GET  /api/v1/messages?type=&read=&cursor=
GET  /api/v1/messages/unread-count
GET  /api/v1/messages/{id}
POST /api/v1/messages/{id}/read

GET  /api/v1/announcements
POST /api/v1/announcements
PATCH /api/v1/announcements/{id}
POST /api/v1/announcements/{id}/publish
POST /api/v1/announcements/{id}/withdraw
```

## 五、风险与回滚

- 风险：接收范围展开产生大量行。缓解：批处理、索引和按用户查询优化。
- 风险：消息摘要泄露越权信息。缓解：按接收权限生成摘要或使用安全通用摘要。
- 风险：撤回语义与邮件不可撤回冲突。缓解：站内明确撤回，审计记录邮件已发送事实。
- 回滚：可以停止消费新发布事件，既有消息保持可读；不删除接收记录。

## 六、完成定义

- N01～N08 全部完成。
- 周报和公告均能生成幂等站内消息。
- 已读状态按用户隔离。
- 公告不包含确认回执流程。
- 管理员操作与用户读取均通过权限测试。
