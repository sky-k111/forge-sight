# W03 五类连接器与管理端接入

> 状态：五类连接器与管理端闭环已实现；SQL Server、Oracle 保持 Beta
>
> 目标：按统一契约实现 MySQL、PostgreSQL、MariaDB、SQL Server、Oracle，并让管理员通过一套动态表单完成接入。

## 一、连接器优先级

| 顺序 | 连接器 | 当前状态 | 实施复杂度 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | MySQL | 稳定适配 | 低 | 已迁移到统一契约，作为回归基线 |
| 2 | PostgreSQL | 稳定适配 | 中 | 已完成多 Schema、注释、PK/FK 和方言整改 |
| 3 | MariaDB | 稳定适配 | 低 | 继承 MySQL 扫描逻辑，保留独立类型与会话超时 |
| 4 | SQL Server | Beta | 中高 | 已实现 ODBC、dbo、TOP/OFFSET 和元数据扫描，待真实环境验收 |
| 5 | Oracle | Beta | 高 | 已实现 thin mode、Service Name、Schema 和元数据扫描，待真实环境验收 |

## 二、能力矩阵

| 能力 | MySQL | PostgreSQL | MariaDB | SQL Server | Oracle |
| --- | --- | --- | --- | --- | --- |
| 推荐驱动 | PyMySQL | psycopg | PyMySQL/MariaDB Connector | pyodbc | python-oracledb |
| 默认端口 | 3306 | 5432 | 3306 | 1433 | 1521 |
| 默认 Schema | 数据库名 | public（可选） | 数据库名 | dbo | 登录用户大写名 |
| 服务端限行 | LIMIT | LIMIT | LIMIT | TOP/OFFSET FETCH | FETCH FIRST/ROWNUM |
| 估算计划 | EXPLAIN JSON | EXPLAIN JSON | EXPLAIN JSON/普通 EXPLAIN | SHOWPLAN_XML | EXPLAIN PLAN/可降级 |
| 注释 | information_schema | pg_catalog | information_schema | sys.extended_properties | ALL_TAB_COMMENTS/COL_COMMENTS |
| 初始成熟度 | verified | beta→verified | beta | beta | beta |

MariaDB 不应只把类型改成 `mysql`。可继承 MySQL Adapter，但必须保留 `type=mariadb`，以便记录驱动、版本、方言能力和测试结果。

## 三、数据库特定要求

### MySQL

- 保留 `utf8mb4`；
- 事务和会话设置只读；
- 支持 `MAX_EXECUTION_TIME`；
- Schema 规范为数据库名；
- 修复所有裸表名引用，统一经 Adapter 引用；
- 验证 MySQL 8，不把 MariaDB 特性误认为 MySQL 能力。

### PostgreSQL

- 完成 W02 全部整改；
- 使用真实 PostgreSQL 集成测试；
- 支持多个业务 Schema 和 Schema 限定白名单。

### MariaDB

- 检测服务端版本并保存在测试连接结果；
- 验证 JSON EXPLAIN 是否可用，不可用时使用 MariaDB 计划解析器；
- 检查 `MAX_EXECUTION_TIME`/`max_statement_time` 差异；
- 保持 MySQL 相同资源模型，不重复业务逻辑。

### SQL Server

- 连接字段包含 driver、encrypt、trust server certificate；
- 默认 Schema 为 `dbo`，但允许选择其他 Schema；
- 使用 `sys.tables/sys.columns/sys.extended_properties` 补足注释；
- 限行使用 `TOP` 或 `OFFSET ... FETCH`；
- 连接使用只读账号，`ApplicationIntent=ReadOnly` 只能作为辅助，不能代替权限；
- SHOWPLAN 需要额外权限，未授权时返回 `explain_unavailable` 并启用严格降级；
- Decimal、uniqueidentifier、datetimeoffset、bit 等类型归一化必须测试。

### Oracle

- 支持 service name，SID 作为兼容选项；
- 默认使用 python-oracledb thin mode，确需原生客户端时再启用 thick mode；
- Schema 规范化需处理未加引号对象默认大写；
- 使用 `ALL_TABLES/ALL_TAB_COLUMNS/ALL_CONSTRAINTS/ALL_CONS_COLUMNS`；
- 使用 `ALL_TAB_COMMENTS/ALL_COL_COMMENTS` 读取注释；
- 优先使用 `FETCH FIRST`，兼容旧版本时退化到 `ROWNUM`；
- EXPLAIN PLAN 依赖权限和 plan table，不满足时明确降级；
- NUMBER、DATE、TIMESTAMP WITH TIME ZONE、CLOB 等类型归一化必须测试。

## 四、动态类型 API

新增：

```http
GET /api/datasources/types
```

示例响应：

```json
[
    {
      "type": "sqlserver",
      "label": "SQL Server",
      "default_port": 1433,
      "maturity": "beta",
      "fields": [
        {"name": "driver", "label": "ODBC 驱动", "kind": "text", "required": false},
        {"name": "encrypt", "label": "加密连接", "kind": "boolean", "default": true},
        {"name": "trustServerCertificate", "label": "信任服务器证书", "kind": "boolean", "default": false}
      ],
      "capabilities": {
        "schemas": true,
        "comments": true,
        "foreign_keys": true,
        "views": true,
        "materialized_views": false,
        "explain_cost": false
      }
    }
]
```

主机、端口、数据库、账号、密码和 Schema 是所有关系型连接器的公共字段；`fields` 只描述数据库专属连接项。数据库图标可以由前端按 `type` 映射，但类型可用性、专属字段、默认值和能力以后端为准。

## 五、管理员接入状态机

```text
draft
→ connection_verified
→ schema_selected
→ scanning
→ pending_confirmation
→ indexing
→ ready

任一步失败 → failed（保留错误分类和可重试动作）
```

接入步骤：

1. 选择数据库类型；
2. 填写连接和安全参数；
3. 测试网络、身份、版本和只读能力；
4. 读取并选择业务 Schema；
5. 扫描元数据并展示差异摘要；
6. 管理员确认登记表；
7. 触发该数据源全量语义索引；
8. 索引成功后进入 `ready`，业务端方可选择。

“测试连接成功”不能直接把数据源设置为可问析。

## 六、错误分类

API 返回稳定错误码，不把驱动异常原文直接暴露给前端：

```text
NETWORK_UNREACHABLE
DNS_RESOLUTION_FAILED
AUTHENTICATION_FAILED
DATABASE_NOT_FOUND
SCHEMA_NOT_FOUND
READONLY_ACCOUNT_REQUIRED
DRIVER_MISSING
TLS_CONFIGURATION_FAILED
CONNECT_TIMEOUT
QUERY_TIMEOUT
EXPLAIN_PERMISSION_REQUIRED
UNSUPPORTED_SERVER_VERSION
METADATA_SCAN_FAILED
```

服务端日志保留脱敏诊断信息；前端显示用户能执行的下一步，例如“检查账号是否拥有目标 Schema 的 SELECT 权限”。

## 七、前端要求

- 入口仅位于管理员端；业务人员不能创建或修改数据源；
- 数据源卡片显示业务名称、数据库类型、接入状态、选中 Schema、最近扫描、索引状态；
- 不在业务端暴露主机、端口、用户名和连接选项；
- 新建流程使用分步抽屉或独立页，不把所有字段平铺；
- 数据源能力不足时显示准确说明，例如“查询可用，成本预估未配置”；
- “已验证”和“Beta”必须有真实测试依据；
- 切换数据源后，业务页面只展示该源的指标、表、调查和记忆。

## 八、验收标准

- 五种类型均能从同一 API 被发现；
- 前端不硬编码连接字段；
- 每种连接器均完成登记、测试、Schema 选择、扫描、确认、索引和问析闭环；
- 连接错误可分类且不泄露凭据；
- 能力不足会降级并可见，不会返回虚假的“可信执行”；
- 删除、停用和修改数据源会正确清理连接池并保留历史证据。
