# W04 契约测试、灰度与回滚

> 状态：单元回归完成；真实数据库契约、性能与灰度验收待完成
>
> 目标：以统一契约证明每个连接器不仅“能连接”，而且可以安全、准确地支撑 ForgeSight 完整问析链路。

## 一、测试分层

### 1. 纯单元测试

- Registry 重复注册和未知类型；
- 标识符引用；
- Schema/表资产规范化；
- 方言 AST 解析；
- 服务端行数限制改写；
- EXPLAIN 结果解析；
- 驱动异常到领域错误码映射；
- 能力降级策略；
- 连接池修订号失效。

### 2. Adapter 契约测试

所有 Adapter 复用同一测试套件：

```python
class AdapterContract:
    def test_connection(self): ...
    def test_schema_discovery(self): ...
    def test_table_and_column_comments(self): ...
    def test_primary_and_foreign_keys(self): ...
    def test_readonly_query(self): ...
    def test_write_is_rejected(self): ...
    def test_timeout(self): ...
    def test_server_side_limit(self): ...
    def test_reserved_identifier(self): ...
    def test_unicode_and_null_values(self): ...
    def test_duplicate_table_names_across_schemas(self): ...
```

目录建议：

```text
backend/tests/adapters/
├── contract.py
├── fixtures.py
├── test_mysql.py
├── test_postgresql.py
├── test_mariadb.py
├── test_sqlserver.py
└── test_oracle.py
```

### 3. 真实数据库集成测试

CI 或专用测试环境启动真实数据库，不使用 SQLite 模拟数据库方言。测试数据库包含相同业务夹具：

- 两个 Schema 下的同名表；
- 中文表/字段注释；
- 主键、复合键和跨表外键；
- Decimal、日期时间、布尔值、NULL 和大文本；
- 至少一张大表用于超时和成本门控；
- 一个只读账号和一个故意权限不足账号。

Oracle 镜像和驱动较重时，可以在普通 PR 中运行契约单测，在 nightly/手动发布流水线运行真实 Oracle；未跑真实测试的版本只能标记为 Beta。

### 4. 端到端问析测试

对每种连接器运行同一组业务问题：

1. 按产线统计最近七天产量趋势；
2. 找出不良数量最高的五个产品；
3. 比较本月与上月良率；
4. 查询不存在的指标或对象；
5. 生成需要澄清时间范围的问题；
6. 尝试访问未登记表；
7. 触发高成本查询；
8. 输出表格、KPI 卡片和趋势图；
9. 回看 SQL、指标口径和证据链。

验收不仅比较是否返回，还比较：

- SQL 方言正确性；
- 查询结果与基准答案；
- 图表类型和轴字段；
- 结论数值是否可由结果表复算；
- 数据源、Schema、表证据是否准确；
- 错误和降级说明是否诚实。

## 二、安全测试

- 写 SQL 和多语句全部在数据库执行前被阻断；
- SELECT-only 账号在数据库层也无法写入；
- 租户 A 无法读取或测试租户 B 的数据源；
- 未选 Schema、未登记表和跨 Schema 越权被阻断；
- 密码、DSN、证书和主机信息不进入 LLM 上下文、前端响应和证据链；
- 日志、错误消息和审计记录不出现明文凭据；
- Schema 名和表名不能通过字符串拼接造成注入；
- 预览、监控、报告、建模和 Agent 使用同一执行边界。

## 三、性能基线

每种数据库记录：

- 首次连接和连接池复用耗时；
- 100/500/1000 张表扫描耗时；
- 语义索引任务耗时；
- 普通查询 P50/P95；
- 超时终止延迟；
- 连接池并发上限；
- EXPLAIN 开销；
- 最大结果内存占用。

扫描大库必须支持批次、进度、取消、失败恢复，不在一个 HTTP 请求中长时间阻塞。

## 四、灰度策略

连接器具有独立开关：

```text
DATASOURCE_MYSQL_ENABLED=true
DATASOURCE_POSTGRESQL_ENABLED=true
DATASOURCE_MARIADB_ENABLED=false
DATASOURCE_SQLSERVER_ENABLED=false
DATASOURCE_ORACLE_ENABLED=false
```

发布批次：

1. 新架构只启用 MySQL/PostgreSQL，验证行为无回归；
2. 对测试租户开放 MariaDB；
3. 对测试租户开放 SQL Server；
4. 对测试租户开放 Oracle；
5. 真实案例通过后逐一升级为 verified。

数据源类型关闭后：

- 禁止新建和新运行；
- 保留历史配置、分析记录、审计和证据；
- 管理员仍可导出诊断信息；
- 不删除资源目录和语义资产。

## 五、迁移演练

迁移前：

- 备份平台 PostgreSQL；
- 统计 `data_source/data_table/table_field/table_relation` 数量；
- 检查每个源是否存在同名表冲突；
- 记录默认源和索引任务状态；
- 停止元数据扫描和语义索引 Worker 的新任务领取。

迁移中：

- 先新增 nullable 字段；
- 回填 Schema；
- 检查重复；
- 建立新唯一约束；
- 更新 ORM 与初始化脚本；
- 恢复 Worker；
- 对每个现有源执行一次扫描 diff，不直接覆盖管理员语义。

迁移后：

- 表、字段、关系数量与预期一致；
- 现有 MySQL/PostgreSQL 数据源仍可查询；
- 现有会话和证据链仍可读取；
- 新资源身份可被检索和引用；
- 需要重建的源进入可观察的全量索引任务。

## 六、回滚方案

代码回滚与数据库回滚分离：

- 代码可切回兼容层继续服务 MySQL/PostgreSQL；
- 新增 Schema 字段和配置字段暂时保留，不做破坏性删除；
- 关闭新连接器开关即可阻止使用 MariaDB/SQL Server/Oracle；
- 新唯一约束出现问题时先恢复旧读取路径，禁止直接丢弃数据；
- 全量索引失败不回滚资源目录，只将数据源标记为“索引未就绪”；
- 任何回滚都保留历史审计、Run、Artifact 和证据链。

## 七、发布门禁

连接器从 Beta 升为 verified 前必须具备：

- 对应驱动和版本清单；
- Adapter 契约测试全部通过；
- 真实数据库集成测试通过；
- 至少一组端到端问析基准通过；
- 安全测试通过；
- 迁移与回滚演练通过；
- 操作手册和常见错误处理完成；
- 前端状态和能力说明与后端一致。
