# T 灰度发布与回滚方案

## 放量顺序

1. 备份平台库，执行可重复迁移；保持调度、邮件关闭。
2. 内部账号开启邮箱门禁，验证注册、绑定、站内消息和文件下载。
3. 开启文件/消息消费者，选择单个内部订阅自动生成；核对冻结版本与证据。
4. 开启邮件 Worker，仅向内部已验证邮箱投递；观察最终失败、P95 和积压。
5. 按组织/订阅分批扩大，至少观察一个完整自然周后全量。

## 独立开关

| 环境变量 | 关闭后的效果 | 保留能力 |
| --- | --- | --- |
| `AUTH_EMAIL_GATE_ENABLED=false` | 暂停强制邮箱门禁 | 既有认证与历史读取 |
| `REPORT_SCHEDULER_ENABLED=false` | 不创建新的周期周报任务 | 历史周报、消息、下载 |
| `MAIL_WORKER_ENABLED=false` | 不领取/发送邮件任务 | 自动发布、站内消息、文件 |
| `AGENT_WORKER_ENABLED=false` | 停止全部后台循环 | Web/API 历史读取 |

所有开关在进程启动时读取，修改后重启后端。

## 回滚演练

- 邮件异常：关闭邮件 Worker，确认站内新周报仍发布；修复配置并验证后重开，幂等键防止重复邮件。
- 调度异常：关闭调度，保留历史查询；确认根因后仅补跑缺失周期，不修改已发布版本。
- 应用回退：部署上一兼容版本，保留新增表、字段、事件和文件；不执行破坏性 down migration。
- 错误周报：发布新版本进行替代并保留旧版本审计，不覆盖或删除历史邮件附件指向。
