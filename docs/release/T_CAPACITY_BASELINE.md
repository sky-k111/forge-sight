# T 性能与容量基线

> 环境：Windows 开发机、SQLite 测试库、Python 3.14。该结果用于发现数量级问题，不代替预发布环境持续压测。

| 场景 | 规模 | 本次结果 | 发布阈值 |
| --- | ---: | ---: | ---: |
| 邮件任务创建（独立且幂等） | 100 接收人 | 0.20 s | < 2 s |
| 邮件任务创建（独立且幂等） | 1,000 接收人 | 1.10 s | < 10 s |
| 典型 PDF 生成 | 2 页 / 26 KB | 183 ms，峰值 5.0 MiB | < 5 s |
| 典型 Excel 生成 | 4 工作表 / 9 KB | 51 ms，峰值 0.69 MiB | < 3 s |
| 长表 PDF | 60 条异常 / 7 页 | 35 KB，逐页无溢出 | < 10 s |
| 前端 Logo | 256×256 | 33 KB（原 5.8 MB） | < 100 KB |

## 运行与扩容建议

- Outbox `pending + retry_wait + processing >= 100` 告警；死信或最终邮件失败立即严重告警。
- 1,000 接收人仍由单事件展开，正式环境应按队列耗时调整 Worker 数量，不增加重复发送语义。
- PDF 是文件阶段主要内存消费者；横向扩容文件 Worker 时共享存储必须保持校验值一致。
- 持续记录真实 PostgreSQL 的 P95，并在接收人达到 10,000 前补分批展开和分页查询压测。
