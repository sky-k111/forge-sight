# T 运维与故障处置手册

## 观察入口

- `GET /health`：进程与数据库基础健康检查。
- `GET /api/v1/operations/metrics`：仅管理员可见，展示调度到期数、Agent/Outbox/文件/邮件状态、邮件耗时 P95、近一小时邮箱安全事件、开关和告警。
- 管理端“公告与投递”页：查看自动化运行状态、最终失败和人工重试入口。

指标响应只含数量、状态、耗时和资源类型，不含邮箱地址、验证码、正文、凭据或原始服务商错误。

## 告警与处理

| 告警 | 级别 | 首要动作 |
| --- | --- | --- |
| `OUTBOX_DEAD_LETTER` | 严重 | 按事件 ID 核对聚合对象，修复原因后显式恢复 |
| `FILE_DEAD_LETTER` | 严重 | 检查存储权限/空间和冻结内容，不直接伪造附件 |
| `EMAIL_FINAL_FAILURE` | 严重 | 查看脱敏分类；配置错误先修配置，地址错误不盲目重试 |
| `SCHEDULER_LAG` | 警告 | 检查调度开关、进程与数据库时钟，避免重复手工补跑 |
| `OUTBOX_BACKLOG` | 警告 | 确认消费者存活，按 P95 与积压量扩 Worker |

## 安全操作

- 改环境变量后必须重启后端；真实 SMTP 授权码只放 `backend/.env` 或密钥服务。
- 邮件故障时设置 `MAIL_WORKER_ENABLED=false`，站内消息、文件和历史下载仍继续。
- 调度异常时设置 `REPORT_SCHEDULER_ENABLED=false`，已发布历史与文件仍可访问。
- 不通过删除 Outbox、投递或冻结版本来“清告警”；保留审计链后使用已有重试/恢复接口。
