# E00 邮件投递与失败重试计划

> 大任务：`E邮件投递与重试`
> 目标：把周报摘要、安全链接和对应版本 PDF，以及管理员公告，可靠发送到用户已验证的任意邮箱。
> 前置依赖：Q、M、R、V、N
> 后续依赖：U、T

## 一、交付边界

本任务负责邮件服务适配、模板、投递任务、重试、状态和管理员重发 API。邮箱所有权验证由 Q 完成，PDF 由 V 生成，站内内容由 N 生成。

## 二、技术原则

- 使用通用邮件适配层，支持 SMTP 或事务邮件 API，不把 QQ 邮箱写死。
- 系统发件凭据只在后端环境变量保存。
- 用户只提供接收邮箱和验证码，不提供邮箱密码或个人授权码。
- 投递任务绑定具体报告/公告版本和接收人邮箱快照。
- 邮件失败不改变站内报告或公告状态。

## 三、执行步骤

### E01 定义邮件提供商接口与配置

1. 定义 `send(message) -> provider_result` 抽象接口。
2. 支持纯文本与 HTML 正文、附件、超时和服务商消息 ID。
3. 配置项包含提供商、服务器、端口、TLS、账号、凭据、发件地址、发件名称和附件上限。
4. 生产日志不得打印认证头、密码或完整邮件正文。
5. 测试环境提供 fake provider，开发环境可选本地捕获服务。

验收：替换提供商不需要修改报告和公告业务服务。

### E02 定义周报与公告邮件模板

1. 周报主题包含产品、报告标题和自然周。
2. 周报正文固定包含标题、周期、版本、3～5 条摘要、最严重异常、数据质量、安全链接。
3. 周报附件只使用 V 发布的对应版本 PDF。
4. 公告模板包含标题、正文、发布人、时间、有效期和站内链接。
5. 同时生成 HTML 与纯文本版本，避免只支持 HTML 的客户端。
6. 所有用户内容经过安全转义。

验收：模板快照测试覆盖中文、长标题、无异常和数据异常版。

### E03 创建幂等投递任务

1. 使用租约消费者领取报告文件就绪或公告发布 Outbox 事件，成功后确认，失败后退避重试。
2. 查询目标用户当前已验证邮箱，保存接收地址快照。
3. 使用 `business_version + user_id + channel` 作为幂等边界。
4. 邮箱未验证、用户停用或无权限时标记 `suppressed` 并记录原因。
5. 批量创建失败只影响对应用户。

验收：重复事件不会重复创建业务投递或重复发信，领取后进程崩溃可由其他 Worker 恢复。

### E04 实现异步发送 Worker

1. Worker 领取 `queued` 或到期 `retry_wait` 任务并设置租约。
2. 发送前再次确认业务版本、PDF 校验值和接收权限。
3. 调用提供商后记录服务商消息 ID、耗时和结果。
4. 进程崩溃后租约过期可安全恢复。
5. 多 Worker 并发时同一投递只能有一个有效发送者。

验收：发送链路不阻塞报告发布请求，崩溃恢复不造成重复发送。

### E05 实现错误分类与重试

1. 区分临时网络错误、限流、服务商 5xx、永久地址错误、附件错误和配置错误。
2. 临时错误默认最多重试 3 次，使用指数退避和随机抖动。
3. 永久错误直接进入 `failed`，不做无意义重试。
4. 配置错误触发管理员告警并暂停批量重试，避免雪崩。
5. 保存每次尝试记录，而不是覆盖最后一次错误。

验收：测试时钟可确定性验证重试时间和上限。

### E06 实现附件降级策略

1. PDF 未就绪时保持任务等待，不提前发送缺附件的正常周报邮件。
2. PDF 生成最终失败时记录阻断原因并允许文件任务修复后恢复。
3. PDF 超过提供商附件上限时发送摘要和安全链接，并标记 `attachment_omitted`。
4. 不自动改发 Excel，避免泄露大量明细。
5. 邮件正文明确说明附件省略原因。

验收：附件异常不会回滚站内报告，也不会静默声称附件已发送。

### E07 实现安全链接

1. 链接使用 `PUBLIC_APP_URL` 和站内报告/公告路由。
2. 不在 URL 中包含邮箱、长期 token 或存储 URI。
3. 未登录时通过前端保存回跳地址，登录后仍由 API 做权限校验。
4. 链接构造统一处理反向代理前缀和 HTTPS。
5. 测试恶意 Host、路径注入和错误环境配置。

验收：复制链接给无权限用户无法获得内容。

### E08 提供投递查询和人工重发 API

1. 管理员可按报告、公告、接收人、状态和时间筛选投递。
2. 展示掩码邮箱、尝试次数、最后错误、下次重试时间和服务商消息 ID。
3. 只允许对可重试或明确修复后的失败任务重发。
4. 人工重发仍复用原业务投递并增加 attempt，避免新建重复业务记录。
5. 所有人工操作写审计日志。

验收：普通用户无法查看其他人的投递或触发重发。

### E09 完成集成、安全与容量测试

1. fake provider 验证主题、摘要、链接、附件内容和 MIME。
2. 测试周报、数据异常版、公告、超大附件和无效邮箱。
3. 测试并发 Worker、超时、限流、崩溃和重复事件。
4. 扫描日志和错误响应，确认无凭据、验证码或敏感正文泄漏。
5. 对目标用户量做批量发送基准，验证限速和队列积压指标。

验收：关键触达路径自动化测试通过，容量和重试行为有数据记录。

## 四、环境变量建议

```text
MAIL_PROVIDER
MAIL_FROM_ADDRESS
MAIL_FROM_NAME
SMTP_HOST
SMTP_PORT
SMTP_USERNAME
SMTP_PASSWORD
SMTP_USE_TLS
MAIL_TIMEOUT_SECONDS
MAIL_ATTACHMENT_MAX_BYTES
PUBLIC_APP_URL
```

`.env.example` 只提供空值或安全示例，不提交真实凭据。

## 五、风险与回滚

- 风险：邮件服务限流导致积压。缓解：速率限制、重试退避、积压告警。
- 风险：重复发送影响用户。缓解：业务幂等键、发送租约和服务商响应记录。
- 风险：PDF 泄露越权数据。缓解：发送前校验版本接收权限，必要时按权限分群生成文件。
- 回滚：关闭邮件 Worker 或具体订阅渠道，站内消息继续工作；保留投递记录供恢复。

## 六、完成定义

- E01～E09 全部完成。
- 任意已验证邮箱能接收周报和公告。
- 正常大小的周报邮件包含摘要、安全链接和正确版本 PDF；超限时显式降级并留痕。
- Excel 不默认作为附件。
- 发送失败可分类、重试、查询和人工重发。
- 邮件故障不影响站内发布。
