# U00 Web 端周报、消息与邮箱交互计划

> 大任务：`UWeb端交互`
> 目标：在 ForgeSight Web 端完成邮箱门禁、消息中心、精美周报阅读、下载、公告管理和投递失败管理体验。
> 前置依赖：Q、R、V、N、E 的稳定 API
> 后续依赖：T

## 一、交付边界

本任务负责 Web 页面、组件、状态管理、API 接入、响应式和可访问性。不实现后端业务逻辑，也不以假数据或固定延迟冒充 Agent 进度。

设计平台已确定为 Web。任何 UI 代码开始前，必须先完成 U01 和 U02 并获得产品确认。

## 三、执行步骤

### U01 完成用户与竞品设计研究

1. 明确桌面管理层、桌面业务人员和移动端临时阅读三类使用场景。
2. 评估 4～6 个真实产品的报告阅读、指标摘要、订阅消息和异常表格设计。
3. 总结用户已熟悉的行业模式和 ForgeSight 的一个差异点：结论与证据同屏可追溯。
4. 从专业经营简报、制造业控制室信息层级和编辑式年报中选择 2～3 个非模板化视觉参考。
5. 输出研究结论并由产品确认，不直接进入编码。

验收：研究明确谁在什么环境中阅读、最先寻找什么信息，以及哪些视觉模式不能照搬。

### U02 完成设计 brief 与 token 审批

1. 定义标题与正文最多两套字体、字号比例、行高和舒适行长，并说明适合中文经营报告的原因。
2. 定义一个主强调色、带色中性色阶和正常/关注/预警/严重语义色，所有对比度达到 WCAG AA。
3. 定义 8px 间距系统、组件圆角层级、表格密度和图表 token。
4. 画出邮箱绑定、消息中心、周报列表、周报详情、公告管理和投递失败页的信息层级。
5. 为每个关键页面设计加载、空、错误、权限不足和成功状态。
6. 给每个主要决策记录两个未采用方案及原因。
7. 输出完整 Web token 和 A4 PDF 对应关系，获得确认后才开始 U03。

验收：设计 brief 被确认，后续实现不出现未批准的颜色、字体和随意间距。

### U03 实现邮箱绑定与验证门禁

1. 登录与注册表单增加明确的邮箱字段和说明。
2. 未验证用户进入专门绑定页，不能看到工作台壳层内容。
3. 验证码输入支持粘贴、倒计时、重发和错误恢复。
4. 更换邮箱说明验证新邮箱前的影响。
5. 按钮使用“发送验证码”“验证并进入工作台”等动宾文案。

验收：新用户和存量用户均能完成流程，错误信息明确且不责怪用户。

### U04 实现消息中心

1. 在全局导航提供消息入口和未读数。
2. 页面提供全部、Agent 周报、管理员公告分类。
3. 支持已读/未读、时间和重要程度筛选。
4. 消息行展示来源、标题、两行摘要、时间、状态和主操作。
5. 打开详情后调用已读 API，未读数即时更新并能在失败时恢复。
6. 空状态说明当前没有哪类消息，不使用通用空盒子插画。

验收：用户可以在不打开每条消息的情况下判断优先级和下一步。

### U05 重构周报列表

1. 去除人工“待复核”作为新周报主流程的呈现。
2. 列表展示周期、版本、总体结论、严重异常数、数据完整度和发布时间。
3. 支持周期、报告类型、组织范围、异常等级和已读状态筛选。
4. 每行提供查看详情、下载 PDF 和下载 Excel。
5. 真实展示生成、校验、附件和投递状态，不使用假动画。

验收：列表能区分生成中、已发布、数据异常和渠道失败，不混淆报告与邮件状态。

### U06 实现精美周报详情布局

1. 采用编辑式报告页面而非相同卡片平铺：顶部是报告身份与总体结论，中部是指标和图表，后部是异常、行动及证据。
2. 首屏依次突出标题/周期、总体结论、关键指标和最严重异常。
3. 加入有业务意义的授权图片或数据洞察主图，显示说明和来源；失败时使用内容相关降级，不显示破图。
4. 使用折线图、条形图、Pareto、热力图或散点图回答具体问题，禁止 3D 图表和无意义饼图。
5. 异常与行动使用可比较表格：数字右对齐、表头固定、合理列宽、长文本换行。
6. 证据面板展示指标口径、数据范围、Artifact 和受权限保护的 SQL 入口。
7. 下载按钮明确区分 PDF 与 Excel，并展示文件未就绪/失败状态。

验收：1440px 桌面首屏可完成一分钟阅读目标，375px 下无内容被截断或不可操作。

### U07 实现管理员公告与投递管理

1. 管理员公告表单包含标题、正文、优先级、接收范围、置顶和有效期。
2. 发布前显示接收人数和影响摘要。
3. 投递管理页按状态、报告/公告、时间和接收人筛选。
4. 展示掩码邮箱、尝试次数、错误原因和下次重试。
5. 手动重发需要明确操作结果，不重复创建业务投递。

验收：业务用户看不到管理写操作，管理员能定位失败任务。

### U08 完成响应式、可访问性与动效

1. 在 375px、768px、1024px 和 1440px 检查布局。
2. 所有交互可用键盘完成，焦点顺序与视觉顺序一致。
3. 图片有替代文本，图表有文字摘要，状态不只依赖颜色。
4. 正文对比度至少 4.5:1，大文本和非文本 UI 满足相应标准。
5. 动效仅用于面板展开、筛选切换和状态反馈，200～500ms，并尊重 `prefers-reduced-motion`。
6. 表格小屏允许横向滚动，同时保留首要列上下文。

验收：关键页面通过键盘、屏幕阅读语义和对比度检查。

### U09 完成浏览器测试与视觉评分

1. 为 API 状态和关键交互补充 Vitest/Testing Library 测试。
2. 在真实浏览器验证邮箱绑定、消息、周报和管理员流程。
3. 检查控制台错误、失败网络请求和重复请求。
4. 对周报首屏、长报告、空状态、数据异常版和移动端截图做视觉检查。
5. 使用 senior-designer Web 检查表逐项评分，所有适用项通过后才交付。

验收：测试与视觉检查均有证据，不能只根据代码推断页面正确。

## 四、周报页面推荐结构

```text
报告身份与下载操作
总体结论 + 数据可信度
关键指标带
业务图片 / 数据洞察主图
趋势与结构分析
异常明细表
重点进展
行动建议表
数据质量
证据与附录
```

## 五、风险与回滚

- 风险：页面为了“精美”牺牲信息密度。缓解：管理摘要优先，长明细渐进披露。
- 风险：图片沦为无关装饰。缓解：强制图片与结论关联、标题、来源和替代文本。
- 风险：复杂图表影响移动端。缓解：小屏保留结论与关键值，图表提供滚动或简化视图。
- 回滚：通过路由或功能开关保留旧报告页，API 契约不回退；新页面稳定后再删除旧主流程。
