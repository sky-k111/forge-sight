# N00 站内消息中心与管理员公告计划

> 大任务：`N消息中心与公告`
> 目标：为 Agent 周报和管理员公告提供统一、可筛选、按用户记录已读状态的站内消息入口。
> 前置依赖：M 消息/公告模型，Q 用户身份
> 后续依赖：E、U、T

## 一、交付边界

本任务负责消息与公告后端领域服务和 API，不负责邮件传输、周报正文生成或 Web 页面实现。消息中心不是聊天系统，不实现回复和确认回执。

## 二、现有代码接入点

- ORM：`backend/app/db/models.py`。
- 路由注册：`backend/app/main.py`、`backend/app/api/`。
- 鉴权：`backend/app/auth/deps.py`。
- 审计：`backend/app/audit/service.py`。
- 前端导航：`frontend-new/src/app/navigation.js`、`frontend-new/src/app/routeConfig.js`。

## 三、执行步骤

### N01 定义消息类型与展示契约

1. 类型首期限定为 `weekly_report` 和 `admin_announcement`。
2. 定义优先级、置顶、有效期、撤回和已读语义。
3. 定义两行摘要、来源标签、主操作和次操作字段。
4. 周报消息绑定具体 `version_id`，公告绑定具体公告版本。
5. 响应中不直接携带越权正文或文件地址。

验收：一个列表响应足以渲染消息卡片，不需要前端推断业务规则。

### N02 实现消息创建与接收人展开服务

1. 使用租约消费者领取持久化发布事件，成功后确认，失败后退避重试或进入死信。
2. 调用 M 的统一范围解析服务处理用户、角色、部门、区域、岗位和组织范围。
3. 对每个接收人创建 `MessageRecipient`。
4. 使用事件 ID 和用户 ID 保证幂等。
5. 对无效、停用或无权限用户记录跳过原因。
6. 大批量接收人采用分批事务，单个用户失败不回滚全部用户。

验收：重复消费发布事件不会产生重复站内消息。

### N03 实现消息列表、未读数与筛选 API

1. 支持全部、周报、公告分类。
2. 支持已读/未读、时间、优先级和关键词筛选。
3. 返回分页游标或稳定分页参数，排序使用置顶、发布时间和 ID 保证稳定。
4. 未读数按当前用户计算，不能接收前端传入任意 ownerId 越权查询。
5. 过期或撤回消息按产品规则展示或隐藏。

验收：用户只能列出自己的消息，分页无重复或遗漏。

### N04 实现已读操作

1. 打开消息详情或显式操作时标记当前用户已读。
2. 已读操作幂等，多次调用返回相同结果。
3. 记录首次已读时间，不因重复打开而覆盖。
4. 支持单条已读；“全部已读”可作为后续能力，不阻塞首期。
5. 公告无需确认回执，不建立确认状态。

验收：两个用户对同一消息的已读状态互不影响。

### N05 实现管理员公告草稿与发布

1. 只有管理员可创建和修改草稿。
2. 字段校验覆盖标题、正文、优先级、接收范围、置顶和有效期。
3. 发布前计算预计接收人数，管理员确认后冻结公告版本。
4. 公告状态与统一 Outbox 发布事件在同一事务提交，触发站内消息和后续邮件任务。
5. 普通业务用户无法调用管理端写接口。

验收：公告发布后目标用户可见，非目标用户不可见。

### N06 实现公告撤回与过期

1. 管理员可以撤回已发布公告并填写原因。
2. 撤回不删除公告和消息，接收人看到明确撤回状态。
3. 到期公告按时间自动变为过期或在查询时计算过期状态。
4. 置顶只在有效期内生效。
5. 撤回和过期不要求撤回已发送邮件，但记录渠道状态。

验收：公告生命周期可审计，历史记录不被物理删除。

### N07 实施权限和内容安全

1. 周报消息详情再次校验报告和版本权限。
2. 公告接收范围由服务端解析，不信任前端提交的接收人数。
3. 正文输出采用安全渲染策略，禁止注入脚本。
4. 消息摘要不包含用户无权查看的明细。
5. 管理员查询发送结果也遵守管理权限和审计要求。

验收：越权读取、跨用户标记已读和公告脚本注入测试通过。

### N08 完成测试与事件集成

1. 单元测试覆盖筛选、排序、未读和生命周期。
2. 集成测试覆盖周报发布事件到消息创建。
3. 集成测试覆盖公告发布到多用户消息。
4. 并发、重复事件、领取后崩溃和死信恢复测试验证唯一约束与可恢复性。
5. 生成 OpenAPI 示例供 U/E 对接。

验收：消息与公告测试全绿，接口契约稳定。

## 四、API 建议

```text
GET  /api/v1/messages?type=&read=&cursor=
GET  /api/v1/messages/unread-count
GET  /api/v1/messages/{id}
POST /api/v1/messages/{id}/read

GET  /api/v1/announcements
POST /api/v1/announcements
PATCH /api/v1/announcements/{id}
POST /api/v1/announcements/{id}/publish
POST /api/v1/announcements/{id}/withdraw
```

## 五、风险与回滚

- 风险：接收范围展开产生大量行。缓解：批处理、索引和按用户查询优化。
- 风险：消息摘要泄露越权信息。缓解：按接收权限生成摘要或使用安全通用摘要。
- 风险：撤回语义与邮件不可撤回冲突。缓解：站内明确撤回，审计记录邮件已发送事实。
- 回滚：可以停止消费新发布事件，既有消息保持可读；不删除接收记录。

## 六、完成定义

- N01～N08 全部完成。
- 周报和公告均能生成幂等站内消息。
- 已读状态按用户隔离。
- 公告不包含确认回执流程。
- 管理员操作与用户读取均通过权限测试。
