# Q00 邮箱绑定与验证计划

> 大任务：`Q邮箱绑定与验证`
> 目标：在保留账号密码登录的前提下，要求所有用户绑定并验证任意有效邮箱，为周报和公告邮件提供可信接收地址。
> 前置依赖：无
> 后续依赖：M、N、E、U

## 一、交付边界

本任务负责用户邮箱身份，不负责周报邮件正文和业务消息。交付包括用户邮箱字段、验证码挑战、注册与存量账号绑定流程、受限登录门禁、安全频控和审计。

不在本任务中实现：周报发送、公告发送、通知偏好和邮件失败管理页面。

## 二、现有代码接入点

- 用户模型：`backend/app/db/models.py` 的 `PlatformUser`。
- 认证服务：`backend/app/auth/service.py`。
- 认证 API：`backend/app/api/auth.py`。
- 鉴权依赖：`backend/app/auth/deps.py`。
- 前端认证 API：`frontend-new/src/api/auth.js`。
- 登录/注册页：`frontend-new/src/pages/auth/LoginPage.jsx`。
- 现有认证测试：`backend/tests/test_auth_api.py`、`frontend-new/src/App.test.jsx`。

## 三、执行步骤

### Q01 定义邮箱身份状态与接口契约

1. 定义 `unbound`、`pending_verification`、`verified` 三种状态及转换条件。
2. 明确注册、登录、`/me`、绑定、验证、重发和更换邮箱的请求/响应结构。
3. 规定未验证用户使用受限 token，token 增加 `email_verified` 或 `auth_scope` 声明。
4. 定义错误码：验证码错误、过期、频率过高、邮箱已占用和绑定已完成。
5. 输出 OpenAPI 示例，避免前后端各自猜测状态。

验收：契约能完整描述新用户、存量用户、更换邮箱和验证码失败四条路径。

### Q02 扩展用户模型并编写安全迁移

1. 为 `PlatformUser` 增加规范化邮箱、验证时间和待绑定状态所需字段。
2. 新增 `EmailVerificationChallenge`，包含用途、邮箱快照、验证码哈希、过期时间、尝试次数、发送次数、使用时间、创建时间。
3. 为规范化邮箱建立唯一约束；迁移存量账号时允许邮箱为空。
4. 编写 PostgreSQL 增量迁移和 SQLite 测试初始化兼容逻辑。
5. 验证迁移可重复运行、不会删除已有用户或重置密码。

验收：旧数据库升级后原账号可登录，新字段为空且被正确引导绑定。

### Q03 实现验证码生成、保存和验证服务

1. 使用安全随机源生成六位数字验证码。
2. 数据库仅保存带服务端密钥的哈希，日志不得打印验证码。
3. 默认有效期 10 分钟，重发间隔 60 秒，单挑战错误上限 5 次。
4. 对账号、邮箱和 IP 设置小时级发送限制。
5. 新验证码发出后使同用途旧挑战失效。
6. 成功验证后原子更新用户邮箱和 `email_verified_at`，同时消费挑战。

验收：验证码不可复用，过期、错误次数和频控均有自动化测试。

### Q04 增加验证邮件适配边界

1. 定义独立的验证邮件发送接口，不直接耦合具体 SMTP 厂商。
2. 开发环境提供捕获式实现，仅记录任务状态，不输出验证码到生产日志。
3. 配置发件人、邮件服务连接和超时参数，全部来自环境变量。
4. 发送失败时保留挑战并返回可重试状态，不误报验证邮件已发送。
5. 为 E 任务预留统一 `MailProvider` 契约，但不在此实现周报附件。

验收：服务商可替换，测试可使用 fake provider 验证邮件内容和调用次数。

### Q05 改造注册、登录和当前用户 API

1. 注册请求增加邮箱，不再注册成功后直接获得完整业务权限。
2. 登录成功但邮箱未验证时返回受限会话和明确的下一步动作。
3. `/me` 返回邮箱掩码、绑定状态和验证状态，不返回敏感挑战信息。
4. 增加发送挑战、确认验证和更换邮箱端点。
5. 对已验证邮箱的正常账号保持账号密码登录，不要求每次邮箱验证码。
6. 管理员种子账号进入存量绑定流程，不在代码中硬编码真实邮箱。

验收：现有账号密码能力不回归，未验证用户无法调用业务 API。

### Q06 实施服务端受限访问门禁

1. 在鉴权依赖中区分完整会话和仅邮箱绑定会话。
2. 默认所有业务、报告、管理接口要求完整会话。
3. 只对白名单接口开放受限会话：`me`、绑定、验证、重发、退出。
4. 防止前端绕过绑定页面直接访问 API。
5. 记录邮箱绑定、变更、验证成功、频控拦截和失败尝试审计事件。

验收：使用未验证 token 调用任意报告接口返回统一的 403 业务错误。

### Q07 完成自动化测试与安全检查

1. 后端先写失败测试，再实现模型、服务和 API。
2. 覆盖新注册、存量绑定、更换邮箱、唯一邮箱、过期、重放、并发验证和频控。
3. 验证响应、日志和审计中不泄露验证码、密码哈希和完整 token。
4. 验证邮箱大小写和首尾空格规范化。
5. 前端契约测试覆盖受限状态响应，具体 UI 在 U 任务实现。

验收：认证测试全绿，安全检查未发现秘密或验证码泄漏。

## 四、数据契约建议

```json
{
  "token": "restricted-or-full-token",
  "user": {
    "id": "u_xxx",
    "username": "demo",
    "emailMasked": "d***@example.com",
    "emailStatus": "verified"
  },
  "nextAction": null
}
```

未绑定时 `nextAction` 为 `bind_email`；待验证时为 `verify_email`。

## 五、配置项

- `MAIL_PROVIDER`
- `MAIL_FROM_ADDRESS`
- `MAIL_FROM_NAME`
- `EMAIL_CODE_TTL_SECONDS`
- `EMAIL_CODE_RESEND_SECONDS`
- `EMAIL_CODE_MAX_ATTEMPTS`
- 邮件服务连接信息，命名由 E 任务统一。

真实凭据只进入后端环境变量，不提交 `.env`。

## 六、风险与回滚

- 风险：强制门禁可能锁住全部存量用户。缓解：上线前验证发送服务，提供管理员受审计的绑定修复入口。
- 风险：邮箱唯一约束与历史脏数据冲突。缓解：存量邮箱为空，新增绑定时规范化并校验。
- 回滚：保留新增字段和挑战记录，只通过配置临时关闭业务门禁；不得回滚数据库并丢弃已验证邮箱。

## 七、完成定义

- Q01～Q07 全部完成。
- 新用户和存量用户流程均通过 API 测试。
- 未验证账号无法访问工作台业务接口。
- 任意有效邮箱可完成所有权验证。
- 用户未提交邮箱密码或个人授权码。
- 迁移脚本可在现有平台库安全执行。
