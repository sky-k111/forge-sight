# T00 集成测试、可观测性与发布验收计划

> 大任务：`T集成测试与发布验收`
> 目标：验证 Q、M、R、V、N、E、U 组成的完整闭环，并提供可监控、可迁移、可灰度和可回滚的上线方案。
> 前置依赖：Q～U 全部进入可集成状态

## 一、交付边界

本任务负责跨模块质量和发布准备，不替代各任务自己的单元测试。发现缺陷时回到对应任务修复，不在测试代码里掩盖产品问题。

## 二、执行步骤

### T01 建立需求追踪矩阵

1. 将产品需求文档第 17 节每条验收标准映射到自动化测试或人工检查。
2. 标记责任任务、测试层级、环境和证据位置。
3. 对没有验证方式的需求补测试设计。
4. 确认旧阶段六中已被新需求覆盖的审批和飞书主链路不再作为新流程验收。

验收：所有 P0 需求均有唯一责任人和验证证据。

### T02 完成数据库迁移演练

1. 使用脱敏的现有平台库副本记录迁移前表和行数。
2. 执行所有新增迁移，验证可重复运行。
3. 检查原用户、报告、版本、订阅和飞书历史可读。
4. 创建并查询新邮箱、消息、公告、文件和投递数据。
5. 记录迁移耗时、锁表影响和恢复步骤。

验收：迁移不删除历史数据，应用兼容读取通过。

### T03 构建端到端测试场景

至少覆盖：

1. 新用户注册、验证邮箱、登录和接收周报。
2. 存量用户登录、强制绑定邮箱后进入工作台。
3. 定时任务生成正常周报、自动发布、消息创建、PDF 生成和邮件发送。
4. 关键数据缺失时生成数据异常版周报。
5. 管理员发布公告，目标用户收到站内消息和邮件。
6. PDF 失败、邮件暂时失败、自动重试后成功。
7. 无效邮箱永久失败和管理员手动重发。
8. 新版本替代旧版本，旧邮件仍绑定旧附件。

验收：每个场景包含数据库状态、API 响应、页面表现和渠道结果断言。

### T04 完成权限与安全测试

1. 测试未验证 token 访问所有业务和管理 API。
2. 测试跨用户读取消息、报告、PDF、Excel 和投递记录。
3. 测试普通用户调用公告发布与人工重发。
4. 测试邮件链接复制给未授权账号。
5. 测试验证码重放、暴力尝试、发送频控和邮箱枚举。
6. 扫描日志、生成文件和错误响应中的秘密与敏感信息。

验收：不存在已知越权路径，安全日志不泄露敏感数据。

### T05 完成幂等、并发与恢复测试

1. 多调度器同时命中同一订阅。
2. 发布事件、文件事件和消息事件重复投递。
3. 多邮件 Worker 同时领取同一任务。
4. Worker 在写结果前后崩溃并恢复。
5. 数据库短暂不可用、邮件限流和文件存储超时。
6. 验证最终只有一个报告版本、一个用户消息和一个业务投递。

验收：所有重试均符合至少一次执行下的业务幂等目标。

### T06 完成性能与容量测试

1. 测量典型报告与大报告的 Agent 生成时间。
2. 测量 PDF/Excel 生成时长、内存和文件大小。
3. 测试 100、1,000 和目标规模用户的消息与邮件任务创建。
4. 测试消息列表、未读数和投递管理查询性能。
5. 定义队列积压、失败率和生成时长告警阈值。

验收：形成容量基线和可执行扩容建议，不以开发机单次结果替代。

### T07 完成视觉与文件质量验收

1. 在 375px 与 1440px 真实浏览器检查周报、消息和邮箱页面。
2. 检查正常周报、数据异常版、长表、长标题和无图片素材状态。
3. 验证业务图片清晰、相关、有来源和替代文本。
4. 验证图表单位、图例、标签、色彩语义和正文数值一致。
5. 渲染 PDF 每一页，检查缺字、模糊、重叠、孤立标题和表格跨页。
6. 打开 Excel 检查工作表、类型、冻结表头、列宽和权限范围。

验收：Web 和文件均达到需求中的精美布局、图片、图表和表格标准。

### T08 建立监控、仪表盘与告警

1. 监控计划命中率、生成成功率、发布成功率和各阶段耗时。
2. 监控 PDF/Excel 成功率和生成时长。
3. 监控消息创建失败、邮件首次成功率、最终失败率和队列积压。
4. 监控验证码发送异常、频控命中和验证失败率。
5. 告警包含业务 ID 和可操作原因，但不含敏感正文或凭据。

验收：值班人员可以从告警定位到报告、文件或投递记录。

### T09 制定灰度发布和回滚方案

1. 首先只为内部测试用户启用邮箱绑定和自动周报。
2. 按模板、组织或订阅分批放量。
3. 设置调度、邮件 Worker 和强制邮箱门禁独立开关。
4. 明确停止新任务、排空队列、恢复处理和替代错误报告步骤。
5. 数据库回滚不删除新字段和历史事件，应用回滚保持向前兼容。

验收：演练关闭邮件而保留站内发布，以及关闭调度而保留历史读取。

### T10 完成发布评审与交接

1. 汇总需求追踪矩阵、测试结果、性能数据、截图、PDF 和 Excel 样例。
2. 更新 `.env.example`、运维手册、故障排查和管理员使用说明。
3. 核对所有前置 PR 已合并且无未处理的重要审查意见。
4. 运行后端、前端和迁移全量验证并保存命令结果。
5. 完成产品、研发、测试和运维发布评审。

验收：发布清单签署完成，已知限制和回滚负责人明确。

## 三、最低测试矩阵

| 层级 | 范围 |
| --- | --- |
| 单元 | 验证码、状态机、幂等键、校验规则、重试计算、模板渲染 |
| 服务集成 | 数据库迁移、Agent 发布、消息创建、文件、邮件提供商 |
| API | 认证、报告、消息、公告、下载、投递管理和权限 |
| 前端 | 路由、表单、筛选、状态、下载和错误恢复 |
| 浏览器端到端 | 注册到收信、周报自动发布、公告发布、失败重试 |
| 视觉与文件 | 响应式截图、PDF 逐页、Excel 打开与类型检查 |
| 非功能 | 并发、恢复、容量、安全、审计和告警 |

## 四、风险与回滚

- 风险：只验证“成功路径”。缓解：T03～T05 把失败、重复、崩溃和越权列为硬性场景。
- 风险：邮件真实送达受外部服务影响。缓解：fake provider 做确定性测试，预发布环境补真实域名测试。
- 风险：视觉验收主观。缓解：使用明确需求、固定视口、样例数据和逐项检查表。
- 回滚：按调度、邮件、门禁三个开关独立降级，站内历史内容保持可用。

## 五、完成定义

- T01～T10 全部完成。
- 产品需求中的 P0 验收项全部有证据。
- 数据迁移、安全、幂等、恢复、容量和视觉质量均通过。
- 后端与前端全量测试通过；如果存在基线问题，必须先修复或经团队明确书面接受，不能误报全绿。
- 灰度、告警、回滚和运维交接可实际执行。
