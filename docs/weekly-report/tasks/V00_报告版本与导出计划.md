# V00 报告校验、版本冻结与 PDF/Excel 导出计划

> 大任务：`V报告版本与导出`
> 目标：建立自动发布前的确定性校验、不可变版本规则，以及与站内版本一致的 PDF/Excel 文件生成和鉴权下载。
> 前置依赖：M 领域模型
> 协作依赖：R 调用校验器并发布；E 使用 PDF；U 使用下载 API

## 一、交付边界

本任务负责结构化报告校验、文件生成、文件存储元数据和下载鉴权。不负责报告内容的 Agent 生成、消息创建或邮件发送。

## 二、现有代码接入点

- 现有 HTML 导出：`backend/app/reports/service.py::export_html`。
- 现有导出 API：`backend/app/api/reports.py`。
- 现有报告详情：`frontend-new/src/pages/business/ReportDetailPage.jsx`。
- 模型与 Artifact：`backend/app/db/models.py`。
- 测试：`backend/tests/test_reports.py`。

## 三、执行步骤

### V01 定义结构化周报 schema

1. 为报告身份、摘要、指标、趋势、异常、进展、建议、数据质量和附录定义版本化 schema。
2. 数值字段使用数值类型和单位，不只保存格式化字符串。
3. 每条重要结论保存证据引用和置信度。
4. schema 增加 `schema_version`，为未来升级保留转换器。
5. API 和文件生成均消费同一结构化内容。

验收：页面、PDF、Excel 不需要分别解析不同来源的数据。

### V02 实现自动发布硬校验

1. 校验必需章节和报告身份信息。
2. 校验正文数值与结构化指标结果一致。
3. 校验比较周期完整性和时间范围一致性。
4. 校验结论具有证据引用。
5. 校验原因措辞与证据状态。
6. 校验接收范围和敏感字段处理结果。
7. 输出机器可读 `validation_json`，包含规则编号、等级、结果和说明。

验收：任一硬规则失败都会阻止正常周报自动发布。

### V03 实现软校验与可信度计算

1. 检查数据缺失、延迟、临时推导指标和局部章节失败。
2. 根据可解释规则计算章节及整份报告可信度。
3. 低可信度结论在正文和 PDF 中明确标识。
4. 严重数据不足时切换数据异常版模板。
5. 可信度算法版本化并写入报告版本。

验收：低质量数据不会被包装成高确定性结论。

### V04 完成不可变版本冻结

1. 结构化正文、数据快照、校验结果、Agent 快照同时冻结。
2. 计算版本内容 SHA-256，后续文件记录该内容校验值。
3. 禁止更新已发布版本的内容字段。
4. 新版本建立替代关系，旧版本保留。
5. 编写服务级与数据库级防覆盖测试。

验收：已发布内容无法被原生成任务或普通更新接口修改。

### V05 实现服务端 PDF 生成

1. 实施前完成 A4 报告设计 brief：明确字体、字号层级、颜色、页边距、栅格、图片比例、图表、表格和页眉页脚 token，并取得确认。
2. 选择可在部署环境稳定运行、支持中文字体的服务端渲染方案。
3. PDF 使用专业编辑式模板，第一页面向管理摘要，后续页面按指标、趋势、异常、行动和证据组织视觉节奏。
4. 每份正常周报至少渲染一项有业务意义的授权业务图片或数据洞察主图，包含标题、来源说明和替代文本元数据。
5. 图表由确定性规格和真实数据渲染，不依赖用户浏览器打印状态；图片保持足够分辨率。
6. 异常明细与行动建议使用真正表格，数字对齐，跨页重复表头，不使用固定行高截断文本。
7. 文件生成到临时位置，成功校验后原子移动到正式存储。
8. 记录 MIME、大小、校验值和生成耗时。
9. 对缺字、图片拉伸、图表模糊、文字溢出、孤立标题、断页和长表进行逐页渲染回归测试。

验收：PDF 可在无浏览器用户会话时生成，内容与已发布版本一致，逐页视觉检查无缺字、模糊、截断、重叠和表格溢出。

### V06 实现 Excel 明细导出

1. 创建“指标概览、异常明细、行动建议、数据来源与口径”工作表。
2. 数值使用真实数值单元格，日期使用日期类型，避免全部写成文本。
3. 每个工作表包含报告周期、版本和导出说明。
4. 仅导出已授权范围的数据。
5. 对空数据、长文本、大量异常明细和特殊字符进行测试。

验收：Excel 能被常用表格软件正常打开，内容与站内权限一致。

### V07 实现鉴权下载 API

1. 使用 `report_id + format` 或 `file_id` 获取文件，不暴露内部存储 URI。
2. 校验登录、消息接收关系、报告权限和数据范围。
3. 返回正确 `Content-Type`、安全文件名和下载头。
4. 对未就绪文件返回明确状态，对失败文件返回可诊断错误。
5. 记录下载审计，不在日志记录敏感正文。

验收：未登录、非接收人和越权用户均无法下载。

### V08 建立文件任务和重试机制

1. 使用租约消费者领取 `report.version.published` Outbox 事件，并按业务键幂等确认。
2. PDF 与 Excel 独立排队、执行和重试。
3. 同版本同格式通过唯一约束去重。
4. 已成功文件默认复用，不重复渲染。
5. 失败记录错误分类和可重试性，超过上限进入可恢复死信状态。
6. PDF 成功与 `report.file.ready` Outbox 事件在同一事务写入，供 E 消费。
7. 测试领取后崩溃、文件写入后崩溃和重复事件，确保最终状态可恢复。

验收：PDF 失败不影响 Excel，文件失败不回滚报告发布，
进程崩溃不丢失文件任务或就绪事件。

### V09 完成测试与基准验证

1. 单元测试覆盖全部校验规则。
2. 集成测试覆盖版本冻结、替代、文件幂等和权限。
3. 保存稳定样例报告的 PDF/Excel 结构断言，并对 PDF 全页图片做视觉回归。
4. 测量典型报告和大报告生成时长、内存和文件大小。
5. 检查生成文件不包含内部存储路径、秘密或越权数据。

验收：导出测试稳定，关键性能数据可用于上线容量评估。

## 四、文件事件契约建议

```json
{
  "eventType": "report.file.ready",
  "reportId": "report_xxx",
  "versionId": "rv_xxx",
  "fileId": "rf_xxx",
  "format": "pdf",
  "checksum": "sha256...",
  "fileSize": 123456
}
```

## 五、风险与回滚

- 风险：服务端中文字体或图表渲染不一致。缓解：固定运行镜像、字体包和视觉回归样例。
- 风险：Excel 包含越权明细。缓解：导出查询复用权限服务，不使用前端已加载数据拼文件。
- 风险：文件存储失效。缓解：文件状态与报告状态分离，支持重新生成。
- 回滚：可以临时关闭新文件任务并保留旧 HTML 预览，但不得把浏览器打印继续宣称为正式服务端 PDF。

## 六、完成定义

- V01～V09 全部完成。
- 自动发布硬校验可阻止错误报告。
- 已发布版本不可变且可建立替代关系。
- PDF 与 Excel 均由服务端生成并受鉴权保护。
- PDF 具有经过批准的精美布局，包含业务图片/洞察主图、真实图表和规范表格。
- PDF 与邮件引用的版本一致。
- 文件失败可重试且不影响站内发布。
