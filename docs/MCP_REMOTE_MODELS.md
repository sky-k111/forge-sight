# MCP 远程模型接入与调用

## 1. 已实现的效果

企业模型继续部署在企业服务器上，ForgeSight 不上传、不下载模型权重。管理员和业务成员都可以在智能建模弹窗中登记自己的远程预测资产，配置数据源、工具和特征字段并完成接口验证；管理员审核后发布，智能分析的 `prediction.run` 和 `modeling.predict` 即可调用远程模型。

入口：

- 业务端：智能建模 → MCP 远程模型。
- 管理端：智能建模 → MCP 远程模型；模型资产 → MCP 远程模型资产。
- 远程资产使用独立注册表与治理入口，不冒充经过本地训练的模型，不污染本地训练评估指标。
- 页面数据源选择保存在 URL 的 `sourceId` 中，刷新当前地址可保留选择。

流程：

```text
管理员批准服务地址 / 保存服务端凭据
    → 页面发现 MCP 工具
    → 管理员或业务成员配置自己的只读 SQL、字段映射、任务类型、版本与业务用途
    → 保存草稿
    → 样例接口验证
    → 管理员发布
    → 业务端预测 / 智能分析匹配调用
    → 结果卡 + 调用状态、条数、耗时记录
```

## 2. 部署准备

安装 `backend/requirements.txt`，其中新增 `jsonschema==4.23.0`。应用启动时的 `Base.metadata.create_all` 会创建新增表；单独管理迁移的部署执行 `database/postgresql/021_remote_model_assets.sql`。此迁移仅新增 `remote_model_asset`、`remote_model_call` 及索引，不删除历史数据，也不修改业务数据库。

在服务端 `backend/.env` 配置（示例域名不是已接通的服务）：

```dotenv
MCP_MODEL_ALLOWED_ORIGINS=["https://models.example.com"]
MCP_MODEL_CREDENTIALS={"enterprise-model":"替换为真实Bearer密钥"}
```

重启后端使配置生效。页面的“服务端凭据名称”填写 `enterprise-model`，不填写密钥本身。无需认证的受信任服务可留空。默认白名单为空，所有地址均被拒绝；应只允许受控服务器，生产环境使用 HTTPS 并配置网络出口策略。MCP 模型凭据和用于智能问析的 LLM Key 是两套配置。

本轮没有修改真实 `.env`、没有导入外部企业模型，也没有将示例域名加入白名单。尚需提供真实服务地址和认证信息才能完成企业实际联调。

## 3. 外部模型的接口约定

支持 MCP Streamable HTTP POST，JSON 或 SSE 响应，`initialize`、`notifications/initialized`、`tools/list`、`tools/call`。协议协商接受 `2025-11-25`、`2025-06-18`、`2025-03-26`。支持服务返回的会话 ID 和工具列表分页。

当前是明确约束的**预测接口适配**，不是任意 MCP 工具执行器：

- 工具须声明 `annotations.readOnlyHint: true`；这个声明不是沙箱，管理员仍须审核实际服务行为。
- `inputSchema` 使用对象结构，记录参数默认名为 `records`，可以在页面修改。
- 第一版不支持额外必填工具参数。模型特殊参数应由企业适配服务固定，或发布不同工具。
- 返回 `structuredContent`，其中 `predictions` 数组与输入逐条、同序对应；数组字段名可配置。
- 回归输出有限数值；异常检测输出布尔值；分类、聚类输出字符串、整数或布尔标签。
- 校验工具输入 Schema、服务声明的输出 Schema、预测值类型和条数；外部 `$ref` 不会联网下载。
- 发布后若输入或输出 Schema 变化，拒绝调用并要求停用、重新验证。
- 版本字段是管理员登记的服务版本，不代表平台能检查企业服务器是否暗中替换了权重。企业应提供不可变版本地址或版本化工具名。

例如工具接受：

```json
{"records":[{"hours":8}]}
```

工具返回的 MCP result：

```json
{"content":[],"structuredContent":{"predictions":[80]}}
```

若 SQL 返回 `working_hours`，字段映射填写：

```json
{"hours":"working_hours"}
```

系统只发送映射字段。样例验证填入的 JSON 要使用 SQL 列名，例如 `[{"working_hours":8}]`；样例留空则通过只读网关执行所配置 SQL，再取最多 200 条预测。

SQL 的时间范围、排序、特征含义由管理员配置。平台不会自动把所有查询解释成“最近记录”，也不会自动把模型输出理解为下个月的预测；预测期限必须由模型及输入特征正确表达。

## 4. 状态与权限

| 状态 | 允许的下一步 |
| --- | --- |
| draft | 修改配置、验证 |
| validated | 发布；修改配置后退回 draft |
| published | 业务预测、停用；禁止直接修改配置 |
| retired | 修改配置或重新验证后再发布 |

接口需登录。当前企业成员可以发现服务、登记自己的远程模型、修改自己的配置并完成接口验证；其他成员创建的资产以只读方式展示。管理员可以配置企业内全部远程模型，并独占发布和停用权限。所有成员都可在授权数据源范围内执行已发布模型。企业、数据源和资产所有者边界在后端校验；Agent 指定模型调用还检查模型所属数据源是否在当前调用上下文中。

当前授权粒度为企业成员 + 数据源归属，不额外实现行级/部门级授权。需要这些隔离的部署必须先扩展授权和 SQL 过滤，不能把它当作已实现能力。

自动匹配沿用已有业务描述关键词相似度方式，仅考虑已发布且同数据源的远程模型，不是保证正确选型的模型评估器。智能分析经 `prediction.run` 调用时使用资产预配置的只读 SQL；`modeling.predict` 则可提供显式样例记录。

## 5. 安全及边界

- 地址精确 origin 白名单；拒绝 URL 内用户名密码、查询参数及 fragment；禁止重定向，不自动使用系统代理。
- Bearer 密钥仅从服务端配置引用，不写进模型记录或调用记录。
- 单次 1–200 条，映射后的输入最多约 1 MB；单个 MCP 响应最多约 2 MB。
- HTTP 超时 30 秒，流读取另有时间预算检查；完整操作含握手、发现、推理等多次请求，不能等同于整个操作严格 30 秒。
- 不自动重试预测，避免远程重复计算或重复计费。超时后服务端可能仍在执行，平台不能撤销企业服务内的任务。
- 调用表仅记录状态、账号、条数、耗时、时间；原始输入和密钥不记入该表。智能分析结果可按原有证据链规则保存。
- 停用阻止新业务调用；已经发出的远程请求不保证被取消。
- 接口样例验证证明可调用及格式正确，**不证明准确率、业务适用性或未来预测质量**。
- 暂不支持远程训练、微调、异步长任务、OAuth 自动授权、stdio、本地进程启动、旧 HTTP+SSE 双端点传输、断线恢复或任意多模态模型。

## 6. 本地演示服务

从 `backend` 目录运行：

```powershell
.venv\Scripts\python -m uvicorn scripts.mcp_model_demo:app --host 127.0.0.1 --port 8091
```

运维仅在本地演示时允许 `http://127.0.0.1:8091`。页面填写 `/mcp` 地址，发现并选择 `predict_output`，字段映射 `{"hours":"hours"}`，用 `[{"hours":8}]` 验证，发布后再预测。返回 80。

**这是固定乘法的接口演示，不是真实训练模型。** 企业模型只需在同样接口内调用自己的推理服务，不需要搬运权重。
